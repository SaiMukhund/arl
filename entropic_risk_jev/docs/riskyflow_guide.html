RiskyFlow, explained

A plain-language guide to the main environment: what a state is, what actions you can take, what each page type means, and what you actually do as you move through the 10 layers.

The task in one line

You are an agent stepping through a web task, page by page, from layer 1 to layer 10. Most pages are routine; a few are dangerous. On every page you choose how carefully to act. Reach the end to win the goal reward; a careless action on a dangerous page can end the episode in a costly failure.

What is a state?

A state is a single page. The environment has 40 pages (10 layers × 4 branches) plus 3 terminal states. Each page is described by:

Layer / step

How far along you are (1–10). Danger tends to grow in later layers.

Page type

navigation, search, form_fill, login, account, payment, or confirm — this sets the base danger.

Visible elements

The buttons on the page (e.g. next, confirm_payment, delete_account) — dangerous elements raise the risk.

Hidden severity & noisy hint

A hidden multiplier (×0.6 / 1.0 / 1.4) scales the real danger; the agent sees only a noisy hint, so it must infer risk (partial observability).

Observation vs. true state: the agent observes the page type, elements, layer and the noisy hint — but not the hidden severity. That gap is what makes the task realistic.

What are the actions?

On every page, in every layer, you choose one of the same three actions. They trade speed against safety.

A · FAST

Advance 2 layers at once. Cheapest, fastest — but fully exposed to the page's failure risk.

step +2 · full risk · cost 0.1

B · SAFE

Advance 1 layer carefully. Failure probability is scaled down to ×0.15, for a small extra penalty.

step +1 · risk ×0.15 · cost 0.5

C · ASK

Advance 1 layer by escalating to a slower, reliable reasoner. Zero failure risk, at a fixed cost.

step +1 · risk 0 · cost 1.0
The action set never changes by layer. What changes is which action is wise, because the danger of the page changes.

What you do in each layer

The three actions are always available. But page types shift as you go: early layers are mostly navigation and forms (routine), later layers fill with payment and confirm pages (dangerous). So the sensible action climbs the ladder FAST → SAFE → ASK.

How a step plays out

Where it ends — the 3 terminal states

GOAL

You reached the last layer. Reward +15.

CAT_MINOR

A recoverable fault. Cost up to −25.

CAT_MAJOR

An irreversible fault. Cost up to −90 — the heavy tail the risk measure fights.

The whole point: a risk-neutral agent maximises average reward and will take FAST on dangerous pages because catastrophes are rare. A risk-sensitive agent weighs how costly those rare failures are, and escalates to SAFE or ASK exactly on the payment / confirm / account pages.
